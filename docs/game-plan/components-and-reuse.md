# کتابخانهٔ مشترک اجزای «مدار گمشده»

وضعیت: پیاده‌سازی کتابخانه و استفاده در تعمیرگاه؛ مرحلهٔ تازه اضافه نشده است. تاریخ: ۲۰۲۶/۱۰/۰۹.

این سند از داک مراحل ۰۱ تا ۱۲، قواعد مشترک و معیار پذیرش استخراج شده است. هدف آن ساخت دوبارهٔ پنکه، باتری، کابل یا کنترل حرکت برای هر مرحله نیست. هر شیء یک تعریف مشترک دارد؛ نمونه‌های آن شناسه، موقعیت، تنظیمات و وضعیت مستقل دارند.

## مرز مسئولیت‌ها

- **موتور مشترک:** زمان، ورودی، حرکت و برخورد، برق، انتقال انرژی، ابزار اتصال و اندازه‌گیری، ذخیره، سرنخ تدریجی و صدا.
- **اجزای مشترک:** مدل رفتاری و مدل سه‌بعدی یک وسیله، بدون اطلاع از شمارهٔ مرحله یا شرط برد آن.
- **تعریف مرحله:** چیدمان، ارتباط بین وسایل، مانع‌ها، هدف‌ها، دیالوگ و ترتیب رویدادهای داستانی.
- **هنر محیط:** مدل‌های فعلی از جنس هندسهٔ تولیدشده در کد و هم‌سطح دارایی‌های تعمیرگاه هستند. چیدمان نهایی و اجرای روایی مراحل ۲ تا ۱۲ هنوز ساخته نشده است.

مثلاً Fan توان و جهت و شدت باد را تعیین می‌کند. RailCrate با شناسهٔ همان پنکه حرکت می‌کند. مرحله مشخص می‌کند این جعبه در کدام ریل باشد و قفل‌شدنش چه راهی را باز کند. خود پنکه نباید عبارت «مرحلهٔ دوم» یا «برد» داشته باشد.

## خانواده‌ها و قرارداد رفتار

| خانواده / کلاس | قرارداد پیاده‌شده |
|---|---|
| Entity | شناسهٔ ثابت، موقعیت، وضعیت مستقل، reset، snapshot و restore |
| Device | مصرف، روشن/خاموش، ولتاژ ورودی و اندازه‌گیری بدون تغییر وضعیت |
| Source | ولتاژ، سقف توان، قطع اضافه‌بار و بازنشانی |
| Battery | ۷۲ ژول، سقف ۱۲ وات، شارژ و خروجی هم‌زمان ممنوع |
| Capacitor : Battery | ۱ فاراد، ورودی ۱۲ تا ۶ ولت، بازده ۹۰٪ و خروجی تنظیم‌شده؛ انرژی خروجی کامل ۴۸٫۶ ژول |
| Lamp / BeamLamp / Sign / Radio / Heater | مصرف مستقل از ظاهر، نور/صدا/اثر بر اساس وضعیت مدل |
| PulseLatch : TimedDevice | ۶ وات برای یک ثانیه، سپس قفل مکانیکی و مصرف صفر |
| RepairBench : TimedDevice | کار شش‌ثانیه‌ای، قطع برق پیش از اتمام باعث شروع دوبارهٔ کار می‌شود |
| HoldingCoil : Device | مصرف پیوسته؛ برای درِ نیازمند نگه‌داشتن برق یا خدمت دائمی |
| Motor | توان شروع جدا از توان پایدار؛ قطع یا تعویض منبع، نیاز شروع را برمی‌گرداند |
| Fan : Motor | سرعت‌های تنظیم‌پذیر و جهت‌های محدود، شدت باد واقعی برای اجسام دیگر |
| Pump : Motor | ۱۸ وات در شروع و ۶ وات پایدار؛ کاهش سطح آب فقط با شلنگ و مقصد معتبر |
| Platform : Motor | آسانسور، بالابر و ریل؛ توقف ایمن، ادامه از موقعیت توقف و انتقال اجسام روی سکو |
| Conveyor : Motor | جهت قابل تغییر، انتقال جسم روی محور و توقف‌های امن |
| Magnet : Device | جذب جسم فلزی در محدوده، مالکیت جسم و رهاسازی روی نزدیک‌ترین ضربه‌گیر |
| Switch / Breaker / SourceSelector | قطع شاخه، محافظ با ظرفیت مستقل و انتخاب یک منبع بدون موازی‌کردن خروجی‌ها |
| Cable / Hose / Socket | دو سر اتصال، طول، جداسازی، آسیب؛ شلنگ از کابل برق متمایز است؛ جایگاه مالکیت یک جسم دارد |
| Resistor / Divider / Receiver / Antenna | مقاومت نامی، تقسیم ولتاژ زیر بار، توان قطعه، جهت قفل‌شده و کیفیت دریافت |
| Prop / RailCrate / WindProp / Cart | حمل، برداشتن، حرکت روی ریل، قفل انتهایی و واکنش به باد |
| Door / Canopy / Bridge / Ladder | بازشدن با ضامن/حسگر/صفحه، بستن تدریجی و جلوگیری از بسته‌شدن روی مانع |
| WaterBasin / PressurePlate / Jack | سطح آب، وزن واقعی جسم و تکیه‌گاه مکانیکی |
| Mirror / LightSensor / Fog | برخورد و بازتاب پرتو در صفحهٔ افقی پازل، مانع نور و پاک‌شدن مه با تهویه |
| Actor / Guard / Companion | حرکت به هدف، گشت/نظافت/شارژ و دنبال‌کردن/ماندن؛ اگر مسیر بسته است منتظر می‌ماند |
| PathRide / Sequence | عبور روی مسیر ازپیش‌تعریف‌شده و توالی زمان‌دار با پیش‌شرط و توقف قابل جبران |
| Inventory | یک مالک برای هر جسم، ظرفیت حمل و حفظ هویت همان باتری هنگام جابه‌جایی |

سه‌بعدی‌بودن مدل‌ها به معنی شبیه‌سازی فیزیک عمومی نیست. باد، آب، ریل و حمل با قواعد محدود و مشخص داک اجرا می‌شوند. مدل برق وسایل، شبکهٔ تغذیهٔ DC با بارهای تعریف‌شده است؛ Divider برای مدار مقاومتی زیر بار حل عددی دارد. حل‌گر مدار آزادِ بخش آموزشی جدا باقی مانده است.

```text
src/campaign/

  ui/SceneHUD.js  قاب مشترک صحنه، ابزارها، پیام، دفتر و نقاط تعامل
  engine/
    FrameGame.js          حلقهٔ مشترک مرورگر
    ComponentLevel.js     BaseLevel و مرحلهٔ متشکل از اجزا
    createNavigation.js   برخورد و مسیریابی با نقشهٔ تزریق‌شده
    Movement.js           حرکت بدون وابستگی به وسایل تعمیرگاه
    GameInput.js          ورودی موس، کیبورد و لمس
    GameAudio.js          صداهای رویداد و صدای پیوستهٔ تجهیزات
    ComponentInteraction.js  انتخاب، اتصال و اندازه‌گیری
    CampaignStore.js      ذخیرهٔ مرحله و بازپخش در خانه‌های مستقل
    ProgressiveHints.js   سرنخ‌های تدریجی با تشخیص تغییر مانع
```

ارث‌بری برای رابطهٔ واقعی استفاده شده: Fan یک Motor است، Motor یک Device است و Device یک Entity. ارتباط بین وسایل با شناسه و تنظیمات انجام می‌شود؛ برای هر مرحله یک زیرکلاس تازه از Fan یا Battery نمی‌سازیم. مدل‌های رفتاری به DOM و Three.js وابسته نیستند و بدون مرورگر تست می‌شوند.

## استفاده برای توسعه

نمونهٔ زیر صرفاً یک مونتاژ آزمایشی است و مرحلهٔ جدیدی در بازی ثبت نمی‌کند:

```js
import { componentSpec } from './components/index.js';
import { ComponentLevel } from './engine/ComponentLevel.js';

const fixture = new ComponentLevel({
  id: 'developer-fixture',
  components: [
    componentSpec('limitedMains', 'supply'),
    componentSpec('fan', 'fan', {
      position: { x: 2, y: 0, z: 1 },
      speed: 1,
    }),
    componentSpec('woodCrate', 'crate', {
      fan: 'fan',
      from: { x: 3, y: 0, z: 1 },
      to: { x: 5, y: 0, z: 1 },
      travelSeconds: 4,
    }),
  ],
  connections: [{ source: 'supply', target: 'fan' }],
  goals: [{ id: 'moved', test: world => world.get('crate').state.locked }],
});
fixture.update(0.016);
```

برای نمایش، ComponentScene را با scene، materials و fixture.world می‌سازیم و بعد از update مدل، update نمایش را صدا می‌زنیم. برای کنترل وسایل ComponentInteraction همان world را می‌گیرد. خروجی select در حالت hand وسیلهٔ انتخاب‌شده است تا میزبان ابزارهای نزدیک آن را نشان دهد؛ حالت meter تنها داده می‌خواند. متن فارسی، محل کنترل‌ها و روایت را میزبان مرحله تعیین می‌کند.

در هنگام بازبودن دفتر یا مدار، paused را true می‌کنیم؛ مصرف و حرکت متوقف می‌شوند. هنگام خروج، dispose نمایش اجرا می‌شود تا هندسه و متریال‌های اختصاصی آزاد شوند. تکسچرهای مشترک را مالک صحنه آزاد می‌کند.

اتصال معمول با world.connect(sourceId, deviceId, { cable, switches }) انجام می‌شود. یک مصرف‌کننده فقط یک ورودی دارد؛ کابل واحد هم‌زمان به دو مصرف‌کننده وصل نمی‌شود. کلید انتخاب، تنها یکی از منابع مجاز را انتخاب می‌کند. برای شارژ، Charger یک مصرف‌کنندهٔ منبع است و target آن شناسهٔ باتری/خازن است؛ charging بسته باید فعال و پس از جداشدن خاموش شود.

بازچینی گروهی با world.resetObjects(ids) اتصال‌های وابسته را جدا می‌کند و به‌طور پیش‌فرض انرژی خرج‌شده، آیتم‌های جمع‌شده و کارهای کامل‌شده را حفظ می‌کند؛ فهرست preserve قابل تنظیم است.

شناسه‌ها داخل یک مرحله یکتا هستند. وضعیت نمونه‌ها مشترک نیست. راهنمای هر مرحله resolver خودش را به ProgressiveHints می‌دهد؛ هیچ متن راهنمای تعمیرگاه در موتور مشترک نیست.

## استفادهٔ واقعی در مرحلهٔ موجود

- WorkshopGame از FrameGame ارث می‌برد؛ زمان‌بندی مرورگر کپی نمی‌شود.
- حرکت از createNavigation با محدوده و مانع‌های تعمیرگاه ساخته می‌شود. فایل navigation.js فقط آداپتور سازگار با importهای قبلی است.
- ورودی و صدا به GameInput و GameAudio منتقل شده‌اند؛ نام‌های قبلی بازصادر می‌شوند تا کد مصرف‌کننده نشکند.
- مصرف باتری و رفتار ضامن از Battery و PulseLatch استفاده می‌کنند؛ مقادیر بار از presets می‌آیند.
- WorkshopProps اکنون فقط محل قرارگیری دارایی‌های مشترک Cart/Reel/Receipt/Lamp/Radio را تعیین می‌کند.
- WorkshopHUD از SceneHUD ارث می‌برد؛ نام وسایل، هدف، برچسب‌ها، متن مقدمه و قواعد نمایش را به قاب مشترک می‌دهد.
- HintProgress از ProgressiveHints مشترک استفاده می‌کند.
- شکل ذخیرهٔ v1 تعمیرگاه و رفتار فعلی آن حفظ شده است. CampaignStore برای دادهٔ مرحله‌های ساخته‌شده با ComponentLevel، کلید جدا دارد؛ به‌صورت خودکار مراحل آینده را باز یا ثبت نمی‌کند.

## آنچه در هر مرحله هنوز باید تعریف شود

چیدمان و موانع، محل سوکت‌ها، مسیر حرکت و محل امن بازگشت، شناسهٔ ارتباط وسایل، شروط قابل مشاهدهٔ پیشرفت، دیالوگ، دوربین و سرنخ اختصاصی. مثال: کتابخانه قابلیت حرکت همراه را دارد، اما اینکه پیکو چه وقت به صفحه برود و چه بگوید متعلق به سناریوی مرحله است. این تفکیک جلوی بازنویسی اجزا را می‌گیرد؛ جای طراحی معما و تست خود مرحله را نمی‌گیرد.

## بررسی و توسعهٔ بعدی

- `npm test`: آزمون‌های قبلی و آزمون رفتاری کتابخانه.
- `npm run test:components`: تست مستقل اجزا و قراردادهای موتور.
- `npm run test:components:browser`: ساخت، به‌روزرسانی و آزادسازی مدل تمام presetها در Chrome.
- `npm run test:browser`: مسیرهای واقعی تعمیرگاه روی دسکتاپ و موبایل.
- سرور تست: `npm start -- --port 4173`.
- `tests/fixtures/components.html` کاتالوگ توسعه است؛ مرحلهٔ بازی نیست و پوشهٔ tests در انتشار Cloudflare وارد نمی‌شود.

برای افزودن وسیلهٔ واقعاً جدید: کلاس مناسب را از Entity/Device/Motor مشتق کنید، رفتار و تستش را اضافه کنید، سپس آن را در registry، presets و نمایش ثبت کنید. برای تغییر توان، رنگ/مقیاس، محل یا مقصد یک وسیلهٔ موجود، نمونهٔ جدید با تنظیمات بسازید؛ کلاس تازه و کپی فایل لازم نیست.
